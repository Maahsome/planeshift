# Implementation Plan: functional-test

- [x] **🎟️functional-test**
  - **Description:** Add an opt-in, end-to-end functional test suite for the currently implemented `planeshift` CLI. The suite must be runnable through `mise function-test`, keep its test code under `@functional/`, execute the built binary as a subprocess, and exercise the real Cobra/configuration/Plane-client/output path rather than calling resource packages directly. Use a uniquely named, test-owned project and work items so create, read, update, relation, archive, unarchive, search, and delete behavior can be verified and cleaned up safely. Keep deterministic route and model assertions in the existing unit/`httptest` suites; this ticket adds the CLI-level workflow and operator-facing run contract.
  - **Scope:**
    - **In scope:** The new `@functional/` test package and its standard-library subprocess/JSON helpers; the `function-test` task in `@mise.toml`; functional-test prerequisites and cleanup guidance in `@functional/README.md` and the existing `@API_TESTING.md`/`@MANUAL_TESTING.md` documentation; black-box coverage for `@cmd/version/version.go`, `@cmd/project/*.go`, `@cmd/workitem/*.go`, the root and plural aliases registered in `@cmd/root.go`, and the configured output/auth path described by `@PLANE_CLIENT.md`.
    - **Out of scope:** New CLI commands or Plane endpoints, changes to `@projects`, `@workitems`, `@plane`, or production configuration behavior solely to make tests easier; generated/OpenAPI code; a second HTTP client or authentication path; new third-party dependencies; live credentials committed to the repository; destructive operations against pre-existing user resources; replacing deterministic unit tests; and making the Business-license template command or deprecated `/issues/` compatibility calls unconditional when their explicit test preconditions are absent.
  - **Implementation Tasks:**
    - [x] **Govern:** Apply `Owned Domains`, `Forbidden Dependencies & Protected Zones`, `Security & Resilience Hardlines`, `Architectural & Async Invariants`, and `Coding Conventions` from `@CONSTITUTION.md`; use ADR-001 and ADR-002 in `@ARCHITECTURE.md` to preserve the existing `cmd.RootCmd` hierarchy, centralized Viper/environment handling in `@cmd/root.go`, lazy shared `plane.ClientFactory` construction, synchronous execution, and current resource package boundaries. Keep the functional harness test-only and standard-library based (`os/exec`, `encoding/json`, `testing`, and related standard packages), with no production dependency or client seam added. The target-selection policy (live non-production Plane versus Prism/local validation proxy) is not recorded by the Constitution or architecture log; flag that as an uncharted team-review decision and make the proposed target explicit through `PLANE_API_URL` rather than silently defaulting a mutating test to Plane Cloud.
      - *Read the governing Constitution and architecture ADRs; selected an explicit `PLANE_API_URL` target gate and kept the planned harness isolated to black-box standard-library subprocess tests.*
    - [x] **Inventory:** Treat `@MANUAL_TESTING.md`, `@cmd/root.go`, `@cmd/version/version.go`, `@cmd/project/project.go`, and `@cmd/workitem/work_item.go` as the command inventory. Add a coverage matrix in `@functional/functional_test.go` for `planeshift version`; Project `list`, `create`, `create-template`, `get`, `update`, `archive`, `unarchive`, and `delete`; primary Work-Item `search`, `get-by-identifier`, `list`, `create`, `get`, `update`, `delete`, `relations-list`, and `relations-create`; the plural `projects`/`work-items` parent aliases; and the hidden `work-item legacy` `search`, `get-by-identifier`, `list`, `create`, `get`, `update`, and `delete` commands. Keep the primary `/work-items/` route family distinct from the explicitly inventoried legacy `/issues/` family described by `@work/04-work-items.md` and `@workitems/client.go`.
      - *Added `functional/functional_test.go` with black-box coverage entries for every current, alias, and hidden legacy command plus expected usage and required flags.*
    - [x] **Define the execution contract:** Require an explicit opt-in and a non-production target before mutating tests run. Document and validate the existing `PLANE_API_URL`, `PLANE_AUTH_MODE`, and selected `PLANE_API_KEY` or `PLANE_BEARER_TOKEN` settings, plus a required `PLANE_FUNCTIONAL_WORKSPACE_SLUG`; isolate subprocess configuration with a temporary `XDG_CONFIG_HOME` so the test does not read or alter the operator's config file. Add explicit opt-ins such as `PLANE_FUNCTIONAL_INCLUDE_LEGACY` for deprecated compatibility calls and `PLANE_FUNCTIONAL_PROJECT_TEMPLATE_ID` for the Business-license template path. Missing optional preconditions must produce a visible skip/log and a recorded coverage status, never a silent omission; missing core prerequisites should fail the `mise` task with a concise, secret-free diagnostic.
      - *Added `functional/runner_test.go` with opt-in, URL/auth/timeout/workspace validation, non-production protection, allowlisted subprocess environment, isolated `XDG_CONFIG_HOME`, and explicit optional-mode settings.*
    - [x] **Implement the subprocess harness:** Add `@functional/runner_test.go` (or a narrowly scoped equivalent under `@functional/`) with a command runner built on `exec.CommandContext`. Resolve the binary from a task-provided path such as `PLANESHIFT_BINARY`, merge only safe test environment overrides, apply a bounded context timeout, capture stdout/stderr and exit status, and redact configured credential values from failure text. Add helpers to run JSON-producing commands with `--output json`, decode IDs/identifiers/sequence IDs without assuming a fixed numeric representation, assert successful 2xx/empty 204 output, and report command arguments without printing environment secrets. Do not use shell pipelines or direct resource-client calls in the functional package.

    - [x] **Verify root behavior and command discovery:** In `@functional/functional_test.go`, run `version --output json` without Plane credentials when possible and assert valid version JSON, then exercise root help, `project`/`projects` help, `work-item`/`work-items` help, and hidden `work-item legacy` help. Assert that every inventoried operation is registered with the expected positional argument order and that the documented `create-template` required flag and Work-Item required flags are present. Use unique names/identifiers based on a timestamp/process value to avoid colliding with existing data and do not accept arbitrary existing resource IDs as destructive-test targets.
