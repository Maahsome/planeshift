# Implementation Plan: Implement the shared Plane API client foundation

- [x] **🎟️Implement the shared Plane API client foundation**
  - *Completed the PSFT-5 shared Plane client foundation, deterministic tests, documentation, verification, and compatibility checks without adding resource routes or dependencies.*
  - **Description:** Build the smallest reusable Plane API foundation for the 49 future resource slices. The foundation will provide centralized, testable configuration resolution; a standard-library HTTP client; safe authentication and error handling; cursor pagination; rate-limit metadata; dynamic JSON preservation; a separate upload transport; a reusable client/factory seam for `cmd/get`; and deterministic tests. It must not implement resource-specific Plane routes or alter the existing version commands.
  - **Scope:**
    - **In scope:**
      - Extend the shared configuration model in `@config/config.go` and `@config/plane.go`, while keeping Viper/environment loading in `@cmd/root.go`.
      - Add a narrow `@plane` package for client options, URL construction, JSON requests, response metadata, pagination, typed API errors, and upload requests. The package must use only `net/http`, `encoding/json`, and other Go standard-library packages.
      - Add a dynamic JSON/output representation in `@objects/raw_json.go` so resource commands can preserve unknown fields while continuing to use `config.Outputtable` and the existing output dispatch.
      - Add the lazy client/factory registration seam in `@cmd/get/get.go` and `@cmd/root.go`; future resource commands will receive the shared client and will not construct transports, credentials, pagination, or output conversion themselves.
      - Add reusable `httptest.Server` assertions in `@internal/testsupport/http.go` and deterministic coverage for the transport, configuration, output dispatch, command registration, pagination, errors, rate-limit headers, cancellation/timeouts, 204 responses, and presigned uploads.
      - Document the foundation contract and the uncharted client/CLI decision in `@PLANE_CLIENT.md`, with the architectural decision recorded for review in `@ARCHITECTURE.md`.
      - Preserve the restricted configuration-file path and `0600` behavior in `@cmd/root.go`, the existing `@config.Outputtable` contract, the logger setup in `@common/logger.go`, and the build workflow in `@LOCAL_BUILD.md`.
    - **Out of scope:**
      - Implementing any resource-specific endpoint, request/response model, or resource command from `@work/01-projects.md` through `@work/49-idp-group-sync.md`.
      - Adding generated/OpenAPI client code, a new third-party dependency, deprecated `/issues/` aliases, automatic retries, asynchronous processing, persistence, or a broad resource abstraction.
      - Changing the existing `version` or `get version` output defaults and behavior, or requiring Plane credentials for either version command.
      - Live Plane calls or committed credentials. Deterministic unit tests and the checked-in Prism contract in `@spec/plane-api.yaml` are sufficient for this foundation.
