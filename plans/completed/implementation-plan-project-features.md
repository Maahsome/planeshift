# Implementation Plan: project features

- [x] **🎟️project features**
  - **Description:** Implement Jira ticket PSFT-9 / Work 02, the Plane Project Features resource slice. Add the two documented operations—get project features and update project features—using the shared `@plane` client foundation, the existing `@cmd/project` Cobra hierarchy, centralized output dispatch, typed contracts, and deterministic local HTTP tests. The official operation pages define the exact route `/api/v1/workspaces/{workspace_slug}/projects/{project_id}/features/`, a non-paginated `GET`, a partial `PATCH`, seven boolean feature fields, 200 JSON success responses, `projects.features:read`, and `projects.features:write` scopes. Preserve omitted PATCH fields and explicit `false` values, and retain unknown response JSON rather than silently dropping it.
  - **Scope:**
    - **In scope:** The focused `@projectfeatures` resource package and its typed models/client/tests; nested `project features get` and `project features update` commands under `@cmd/project`; safe feature help in `@help/project_help.go` or a focused help file; output adaptation through `@objects/raw_json.go` and `@config/config.go`; the Project Features portion of `@spec/plane-api.yaml`; and narrowly focused command/test support required to verify the slice.
    - **Out of scope:** Workspace Features, Project Labels, any other Plane resource; new transports, configuration paths, authentication headers, pagination implementations, retries, generated/OpenAPI SDK code, third-party dependencies, deprecated `/issues/` aliases, live Plane calls, changes to existing Project operations, changes to root/version output, or undocumented feature flags and validation rules.
