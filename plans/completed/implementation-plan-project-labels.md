# Implementation Plan: Project Labels

- [x] **🎟️Project Labels**
  - **Description:** Implement Jira ticket PSFT-10 / Work 03, the five-operation Plane Project Labels resource. Add the workspace-scoped project-label catalog and CRUD lifecycle using the shared `@plane` client foundation, typed contracts, the existing Cobra/config/output conventions, and deterministic local HTTP tests. The official pages define `/api/v1/workspaces/{workspace_slug}/project-labels/` and `/.../{label_id}/` routes, 201 create, 200 list/get/update, 204 delete, cursor pagination with `order_by`, and `projects.labels:read` / `projects.labels:write` scopes. Preserve label name, color, description, numeric sort order, workspace association, nullable values, and unknown response fields without inventing a project-scoped `/projects/{project_id}/labels/` alias.
  - **Scope:**
    - **In scope:** The new `@projectlabels` route/model package and its tests; a top-level `project-label`/`project-labels` Cobra resource in `@cmd/projectlabel`; lazy registration through `@cmd/root.go`; command constants/tests in `@config/aliases.go`; safe help in `@help/project_label_help.go` and the root help entry in `@help/root_help.go`; focused typed Project Labels schemas and route corrections in `@spec/plane-api.yaml`; and narrowly scoped command/test support needed to exercise all five operations.
    - **Out of scope:** The separate project-scoped `/projects/{project_id}/labels/` Label resource already represented elsewhere in `@spec/plane-api.yaml`, Work Item Labels, Project Features, any other Plane resource, new transports/configuration paths/authentication headers, retries, generated/OpenAPI SDK code, third-party dependencies, deprecated `/issues/` aliases, live Plane calls, changes to existing Project commands, or changes to version/configuration security behavior.
